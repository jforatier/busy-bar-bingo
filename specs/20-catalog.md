How Bingo gets into the [BUSY Apps Catalog](https://github.com/busy-app/busy-apps-catalog) and what the BUSY Bar Apps Hackathon asks.

Sources: the catalog's `CONTRIBUTING.md` and `TERMS.md`, the [official rules](https://busy.app/pages/terms-of-js-apps-contest). Re-read them before submitting: they can change.

## How the catalog builds and checks an app

- Source in a **public GitHub repo**, pinned by a full 40-character `commit_sha`.
- Built by the catalog with `npm ci` (no install scripts) then `busy-cli build`, **without network or secrets**: anything the build needs is in git, or generated by the build itself.
- Automated checks, an AI review of code, texts and images, then a human moderator.
- Each `.js` file ≤ 250 KiB, archive ≤ 100 MB.

## Catalog texts

The texts live in the repo: `catalog.json` (category, short description = the app's reference sentence, shared with the README and the repository's About, changelog; the description points to `CATALOG.md`, written for the catalog's page). The official emulator's `check` reads them with `screenshots/` and runs the catalog's checks locally.

## Contest specifics

- One category per app: **`games`**. Criteria, unweighted: usefulness, originality, code quality, UX and ease of use, aesthetics.
- In the PR template, tick the contest box and the authorship box; declare the AI assistance honestly.
- The entry must be the author's own original work (rule 4.4a): issues open, outside pull requests frozen until the results.
